# Full source integration objective remains open

User objective: combine the supplied applications' actual code and strongest
capabilities into one Loki tool, including MiroFish improving the council,
simulated practice, Paper/Real controls and the eventual 70% trading-win target.
The current implementation is concrete progress, not completion of that scope.

## Verified current behavior

- The interactive synthetic exchange has its own ledger, generated multi-asset
  candles, replay clock, seeded regimes, costs, market/limit paper orders,
  protective stops, journal/export and council feedback. Synthetic outcomes are
  excluded from target evidence.
- The top Paper/Real controls separate practice from real-account inspection.
  Real balance reads use actual CCXT venue code, configured only by the host.
  Switching modes never authenticates, submits orders or starts trading.
- Manual Kraken spot limits have immutable previews, typed confirmation,
  minimum/precision/funds/quote checks, a durable SQLite journal, daily caps,
  duplicate prevention, cancellation and read-only reconciliation. Verification
  uses venue mocks only; no real account or funded order has been tested.
- All 128 original supplied MiroFish files are bundled with hashes and AGPL
  license. The retained native ReportManager file reader and report data classes
  actually execute in a subprocess. Native report artifacts enter the council's
  scenario/sentiment packet, source inspection and review checks without using
  MiroFish's project HTTP API. Structured native fixtures verify this path;
  those fixtures are not reports from a real provider simulation.
- Vibe-derived causal calculations and AutoHedge-derived role contracts run
  inside Loki. Fincept's original licensed analytics run against actual inputs.
- Public historical factor learning trains a fixed market-direction model with
  date-separated evaluation. The measured result does not prove a trading edge.

## Work required before the full objective is complete

1. **MiroFish native simulation pipeline:** connect original graph building,
   ontology/profile/config generation, OASIS social actions, memory updates,
   report generation and report chat as one native Loki workflow. Run genuine
   provider-backed or appropriately implemented local-provider jobs. Dependencies
   and genuine LLM/Zep configuration are currently missing. Source presence and
   fixture-based report reading are not proof these jobs ran.
2. **AutoHedge reasoning and tools:** migrate useful actual agent orchestration,
   research/fundamentals and tool implementations beyond deterministic role
   contracts. Keep free-text outputs separate from execution authority, preserve
   source licenses and test against real task inputs. Native-source presence
   alone does not establish agent reasoning or profitable decisions.
3. **Vibe broader quant/research workflow:** integrate strategy discovery/store,
   hypothesis tracking, portfolio analytics and useful governance/channel/memory
   features. Audit their source contracts and dependencies before making claims.
4. **Fincept broader terminal features:** incorporate the useful licensed
   analytics, data/terminal and portfolio workflows beyond risk reports, within
   the user's confirmed commercial license. Keep private licensed source out of
   public source releases and preserve the intended runtime boundary.
5. **Real execution expansion:** validate the manual Kraken workflow against
   appropriate venue test facilities before funded use; add portfolio-wide
   exposure/drawdown controls, authenticated multi-user operation and other
   venues only after their actual semantics are verified. The current manual
   limit workflow has no autonomous bot or attached protective stops. No broker
   account is authenticated or real order placed by verification runs.
6. **Trading research and forward evidence:** secure usable, commercially
   licensed real execution history and/or collect prospective observations,
   freeze strategy identities/settings, preserve all trials, and test costs,
   regimes, losses and independent dates. An inspected holdout cannot be made
   fresh by retuning or changing provider. Benchmark-factor direction accuracy,
   generated practice wins and software test counts do not prove 70% completed
   real-market winning trades or profitability.
7. **Business deployment:** finish authentication, durable storage, operational
   monitoring, installer/release and deployment verification for the actual
   combined runtime. Review applicable corresponding-source and component
   distribution obligations for the chosen deployment.

Keep the goal active while any explicit requirement remains incomplete or
unverified. A 70% historical sample would still not guarantee future trades.
